This guide is a reference you can return to while you build. Each widget gets its own page with the same layout, so once you learn the shape you can scan any page fast. Read the prose, run the matching demo file, then change it and see what happens — the demos are where the real learning is.

Where the levels sit. Everything in the core pages is reachable at Level 2 (AS91896). For Level 2, two of the named advanced techniques are responding to events generated by a GUI and using a non-core library — and a tkinter program gives you both at once. Pages with an interactive widget also carry a Level 3 lift (AS91906): the same idea moved into a class you define, with file persistence and validation. That single step covers several of the named complex techniques together — a GUI, your own class, and reading/writing to a file.

How each page is laid out

  • What it is — the widget in one or two sentences.
  • When to reach for it — and when a different widget is the better choice.
  • Minimal example — the smallest code that shows it working.

  • Common gotcha — the mistake almost everyone makes once.
  • Practice task — a small thing to build yourself.
  • Level 3 lift — on interactive widgets, how to push it toward complexity.

Label Year 12 · L2

Shows a piece of text (or an image) to the user.

What it is

A display area for a short piece of text or an image. A Label shows information to the user — it does not collect anything from them.

When to reach for it

A title at the top of a window, a prompt sitting next to an Entry, a status line, or the result after a calculation. Not for input — if the user needs to type, use Entry or Text; for a clickable action use Button.

Minimal example

import tkinter as tk

window = tk.Tk()
label = tk.Label(window, text="Kia ora!")
label.pack()
window.mainloop()

Key options

  • text — the words to show.
  • textvariable — link a StringVar so the Label updates itself when the variable changes.
  • font, fg (text colour), bg (background).
  • wraplength — width in pixels at which long text wraps.

Events & value

A Label is output-only — it does not respond to events. You change what it shows in one of two ways: label.config(text="..."), or link a StringVar and call var.set("..."). There is nothing to "read" from a Label; the point is updating it.

Common gotcha

To update a Label live you must use .config() or a StringVar — reassigning the ordinary Python variable does nothing to the screen. And a Label will not wrap long text on its own: set wraplength or it runs off the edge.

Practice task

Make a window with a Label reading Clicks: 0 and a Button. Each click should increase the number shown in the Label.

No Level 3 lift: a Label has no events and is not itself a complex technique. Its role at Level 3 is as the output surface for a richer program — showing computed results, status, and state.

Entry Year 12 · L2 Level 3 lift

A single-line box the user types into.

What it is

A single-line text box the user types into. It is the most common way a tkinter program takes input from the user.

When to reach for it

Whenever you need one line of text or a number — a name, a search term, a score. For several lines use Text; if the user should pick from fixed options use Combobox or Radiobutton rather than making them type.

Minimal example

import tkinter as tk

window = tk.Tk()
name_var = tk.StringVar()
entry = tk.Entry(window, textvariable=name_var)
entry.pack()
window.mainloop()

Key options

  • textvariable — link a StringVar so you can read or set the box.
  • width — width in characters.
  • show="*" — hide the text, for passwords.
  • state="disabled" — make it read-only.

Events & value

Read it with name_var.get(), usually inside a button's command. You can also respond live by binding a key event:

entry.bind("<Return>", lambda event: print(name_var.get()))

Common gotcha

.get() always returns a string, even if the user typed 42. Do maths on it without int() or float() and you will get bugs or a crash — which is exactly why validation matters.

Practice task

Make a window with one Entry and one Button. When the button is clicked, show the typed text in a Label. Then extend it: if the box is empty, show a messagebox warning instead.

Level 3 lift

Everything above earns the "responding to GUI events" technique. To push toward Level 3 complexity, move it into a class and add validation and persistence:

import tkinter as tk
from tkinter import messagebox

class NameApp:
    def __init__(self, root):
        self.var = tk.StringVar()
        tk.Entry(root, textvariable=self.var).pack()
        tk.Button(root, text="Save", command=self.save).pack()

    def save(self):
        name = self.var.get().strip()
        if not name:                        # validation: reject empty input
            messagebox.showwarning("Oops", "Please enter a name.")
            return
        with open("names.txt", "a") as f:   # persistence: write to a file
            f.write(name + "\n")

That one example now shows a GUI, event handling, a class you defined, input validation, and writing to persistent storage — four of the named complex techniques in one place.

Listbox Year 12 · L2 Level 3 lift

A scrollable list of items the user can select from.

What it is

A box showing a scrollable list of items the user can select. It is backed by a collection you add to and remove from as the program runs.

When to reach for it

Choosing one or more items from a list that changes — files, names, tasks. A small fixed set of options is cleaner as Radiobutton or Combobox; free text is an Entry.

Minimal example

import tkinter as tk

window = tk.Tk()
listbox = tk.Listbox(window)
for item in ("Apples", "Kumara", "Bread"):
    listbox.insert(tk.END, item)
listbox.pack()
window.mainloop()

Key options

  • selectmode — "single" (default), "extended", or "multiple".
  • height — number of rows shown.
  • insert(tk.END, item) and delete(index) — add to / remove from the list.
  • get(0, tk.END) — read the whole list back as a tuple.

Events & value

Find what is selected with curselection(), which returns the selected indices; then listbox.get(index) gives the item. React to the user changing the selection by binding the virtual event <<ListboxSelect>>. Adding and removing items is "modifying data stored in a collection" — itself an advanced technique.

Common gotcha

curselection() returns a tuple of indices, which can be empty when nothing is selected. Index into it without checking and the program crashes. Also: a Listbox stores display strings, not your objects — if items carry more data, keep a parallel Python list.

Practice task

Build a list with an Entry and an Add button (reject empty or duplicate items) and a Remove button for the selected item. Show the current selection in a Label.

Level 3 lift

Move the list into a class that loads its items from a file when the app starts and saves on every change:

class TodoApp:
    FILE = "todo.txt"

    def __init__(self, root):
        self.listbox = tk.Listbox(root)
        self.listbox.pack()
        self.load()                          # fill from the file at startup

    def load(self):
        try:
            with open(self.FILE) as f:
                for line in f:
                    self.listbox.insert(tk.END, line.strip())
        except FileNotFoundError:
            pass                             # first run: no file yet

    def save(self):
        with open(self.FILE, "w") as f:
            for item in self.listbox.get(0, tk.END):
                f.write(item + "\n")

A GUI, a class you defined, persistent storage, and collection handling — several complex techniques working together in one small program.
